# 云助手视频识别工具使用说明

当前为实验模块，目标是在用户提供的 WebDAV 实验集达到 95% 以上的正确识别率；尚未完成整库枚举及独立身份核实，不能宣称已达标。它不替换原扫描／整理器。

当前规则版本 v15。在日期、季语法、目录备用标题、AI强核验经验、调用端媒体范围及编号上下文之外，新增声明式NFO输入、对象编号空间、受限作品归属及官方位置核验。v10 两批各 200 作品组回放为 193、194 个候选接受，原先接受身份未变；这不是整库或文件正确率。绝对顺序、外部ID转换及所有作品边界格式仍未完成。

## 本地规则回放

在云助手项目根目录、Node 22 环境运行：

```sh
node --import tsx api/src/media/video-recognition/cli.ts < 目录快照输入.jsonl > 识别结果.jsonl
```

每行一个目录对象，完整快照示例：

```json
{"rootPath":"/媒体","directoryPath":"/媒体/节目示例 (2020)/Season 01","enumerationComplete":true,"files":[{"id":"来源内稳定文件ID","name":"节目示例.S01E02.mkv","size":123456,"etag":"源返回的ETag","modifiedAt":"源返回的修改时间原值"}],"childDirectories":[]}
```

`enumerationComplete` 必须如实提供；分批拉取未结束或子目录读取失败时不能填写 true。文件 ID 是结果关联键，路径由目录和原始文件名生成。禁止把密码、令牌或完整授权 URL 放入快照。

v12 可在每个文件增加 `mediaKind`：`video/audio/other`。调用方应沿用已有默认／自定义后缀设置生成分类；仅未传字段的文件使用原默认16种后缀。显式video参与解析、日期目录、语言目录及AI样本；audio/other不进入视频识别。服务能力为 `callerMediaKind=true`。

自定义后缀仅在旧解析器的私有副本中替换成已支持后缀，返回ID、路径、原文证据和来源修订保持真实值；末尾明确季集／年份／规格不当作后缀删除。APP接入仍需传入它已有的分类结果，本轮未改APP代码。未知后缀也可能是正片，未核实媒体角色前不能据默认表把它们全部移出验收分母。

来源给出 ETag、修改时间和大小时应一并提供，避免同路径内容替换后仍命中旧经验；这些原始字段与规则解析的年份、类型和季集分开。只修正解析规则不会使相同源文件的已确认身份失效。未提供可检测修订时，不保证发现同路径同名的内容替换。

若服务能力 `ancestorDirectoryTitleEvidence=true`，可在原输入增加已读取的祖先目录快照，不带任何来源账号：

```json
{"ancestorDirectorySnapshots":[{"directoryPath":"/媒体/YA-YZ","enumerationComplete":true,"childDirectories":["YA.样例甲","YM.节目示例","YZ.样例乙"]}]}
```

示例对应当前目录 `/媒体/YA-YZ/YM.节目示例`、扫描根 `/媒体`。路径必须是真正祖先且不越过扫描根；每批最多 32 层，每层最多 5000 子目录名。缺省仍兼容原输入，父快照不完整时不能推测字母索引。APP 从已枚举缓存组装，不额外列目录；云助手内部使用相同输入。

## API 调用

模块由云助手原有 API 服务启动时注册，复用已有登录。APP 发送 `Authorization: Bearer <现有登录令牌>`，浏览器也可沿用登录 Cookie；没有新增独立账号。

| 方法和路径 | 说明 |
| --- | --- |
| `GET /api/v1/video-recognition/capabilities` | 规则版本及实际可用能力。 |
| `POST /api/v1/video-recognition/parse` | 发送上述快照，最多 5000 文件，执行纯规则。 |
| `POST /api/v1/video-recognition/resolve` | 发送上述快照，最多 100 文件／20 作品组，使用实例已有 TMDB 配置核对身份；可附稳定的 `sourceScope` 读取本用户已确认经验。 |
| `POST /api/v1/video-recognition/suggest` | 增加 `sourceScope/fileId/modelId`。先查经验和普通识别，仍未确认时请求所选 AI、查询 TMDB；独立强核验通过则自动保存，否则返回待确认建议和 `proposalId`。 |
| `POST /api/v1/video-recognition/confirm` | 在上述快照增加 `sourceScope`、`fileId`、`mediaType`、`tmdbId`，表达用户已明确确认的结果；服务核实官方身份后记录同源精确文件映射。 |

大目录仍提交完整快照，并用 `targetFileIds` 选最多 100 个文件／20 个作品组联网；不能为了分批把部分目录标成完整目录。`items` 保存规则候选与证据；`decisions` 按 `workKey` 给在线决策；`confirmedFiles` 按 `fileId` 给精确身份经验命中，优先应用于该文件。`statistics` 是逻辑调用次数，底层网络重试可能增加实际 HTTP 次数。

`resolve` 另返回逐文件 `fileMappings`。APP 必须按 `fileId` 使用其 `identityStatus`、`placementStatus`、`tmdbId` 和 `episodes`，不能把组上的 `accepted` 直接用于所有节目文件的季集。跨作品边界的组可保持 `pending`，有官方日期＋单集标题证据的子文件仍可单独接受；其他文件保持待确认。v11 自动经验保存实际位置状态，并在命中时返回；旧人工经验没有位置，因此单看 `confirmedFiles` 身份命中仍不能推导季集正确。

日期证据保存在 `episodeEvidence`，旧弱数字留在 `legacyEpisodes`，不再当最终集号。明确季优先，无季日期按官方季摘要每文件最多选两季；同日多集、日期与明确集号冲突、缺资料均保留待核对。整季索引按提供者修订／作品／季／语言缓存并合并在途请求，每批最多 20 次新整季读取；达到预算返回待确认而非猜测。祖先编号来源保存在 `providerIdEvidence`，当前检测明确书名号或年份作品目录边界，完整 NFO 对象类型、其他边界格式及绝对顺序仍待完善。

`dateDirectoryEvidence` 仅在完整日期目录修正候选时返回，包含不同日期数、日期文件占比依据、期／加更标记数量、目录标题候选与原类型／年份。阈值为至少 3 个不同日期、日期起始视频占比至少 60%、至少 2 个期／加更／企划文件；混合桶、合集、扫描根、原显式编号、明确集号、独立电影年份和明确解说受保护。规则候选变为节目仍需系列及位置核验。原有已判节目项不因该规则重写。

`directoryTitleEvidence` 返回有结构依据的备用标题。字母索引要求等宽范围桶、前缀落点、点号分隔、至少三个同形目录且占比 >=60%；向下只穿过明确季／范围／语言／规格节点，不穿过另一作品名。语言版本回找直接有效作品父目录时，当前目录须完整，至少三个视频有集号形态且占比 >=80%。候选保留自己的年份和来源路径，原类型、年份、季集、编号及作品组键不变。原查询成功即停，不因添加备用词再查一遍。

季证据不再从 `第 29 集` 中提取季号，`S1-S10` 等父合集范围也不提供所在季；中文 `第七季` 等明确语法可保留，目录与文件的明确季不相同时 `seasonConflict=true`，位置待确认。没有日期、明确季，也没有可启用的完整编号上下文时，先返回待确认，不额外读一次详情后再得出相同结论。

v13 `completeNumberingContext=true` 时，节目规则结果提供 `numberingContext/sourceOrdinal`。编号在完整目录收集，再用 `targetFileIds` 选择在线目标；至少3个不同编号、编号视频占比>=80%，且无重复、分段、标签／季／ID冲突、混合作品，才启用同级候选。日期排除，阿拉伯明确集号、头部／括号／尾部编号分开记录；不更改原有季集字段。

明确季目录下可将同级编号与官方索引核对；没有明确季时，须官方仅一个普通季，且至少两个不同编号的原文标题锚点与官方同号唯一单集相符，无已识别反例。一般“第N集”等标题不当锚点。候选无足够证据返回 `numberingCandidate` 和缺少条件，`placementStatus=pending/episodes=[]`；它不能被APP当作正式季集使用。多普通季仍需顺序／分组核验，不默认为S01。整季继续共用20次预算和缓存，源范围超出官方索引时保留待确认。

v13同200开发文件回放：身份154接受，位置114 verified+3电影NA=117，原身份和位置无变化，补读16份必要资料。额外两个无季真实目录通过6个和4个标题锚点验证位置，定向HTTP补读3份资料；这些例子不增加200文件分子。较大冻结集182955输出无漏／异常，旧字段逐项不变，只新增原文上下文。仍未完成独立正确率验收。

确认接口会写新增的 `video_recognition_knowledge` 表（数据库版本 66）。若本次用过 AI，确认请求应带服务生成的 `aiProposalId`；服务核对它属于同用户、同来源、同文件，再把相关输入特征、模型修订、AI 建议和最终官方身份一起写入经验。普通 AI 建议只存 `video_recognition_ai_proposals`，30 天内复用建议缓存；网络查询共用普通识别缓存。已确认经验不随建议缓存到期失效。

AI 提示词 v2 要求内容角色、不确定性和连续原文片段。不确定建议或非正片角色不追加 TMDB 查询；节目查询不采用 AI 从单集日期推测的首播年。年份冲突按字段记录，不能因为一个 AI 字段不符而把全部原始特征改掉。

新版服务正常启动时才运行项目已有迁移流程；本轮没有启动部署实例或迁移当前运行数据库。`confirm` 用于人工选择与纠错；自动路径不要求再次人工确认或等待 APP 本地库落库。无 `sourceScope` 的请求仅解析／在线核对，不保存用户经验。模型自报确信不会直接变成身份。

当前支持：原规则目录识别、数字片名保留、有限的有边界类别标签、保守在线候选裁决、显式编号验证、官方别名与地区译名核对、查询合并缓存、显式 AI 建议、受限NFO输入核验、人工确认或完整标题强核验后自动保存 AI 特征及结果，并在同源精确文件复用。尚未接通：现有扫描／整理入口替换、APP 页面、同作品目录新集推广。已完成真实快照规则回放、TMDB 在线核对及本机隔离 HTTP 演示；实际新模型请求到生产落库的整链路未验证。具体规则与持续实验记录见 Flymby 仓库的《鸿蒙APP与云助手扫描识别功能详细实现方案》。

## NFO输入（v14）

能力 `relatedNfoEvidence=true` 时可增加 `sidecarPolicy=use` 和 `sidecars`。未传策略或为ignore时，不解析也不应用NFO，沿用来源已有“忽略NFO”选择；use但未提供sidecars等同本目录没有已读资料。

```json
{"sidecarPolicy":"use","sidecars":[{"id":"来源内稳定NFO标识","path":"/媒体/节目示例/Season 01/节目示例.S01E02.nfo","readStatus":"ok","text":"<episodedetails><season>1</season><episode>2</episode></episodedetails>","etag":"来源原值"}]}
```

最多128份，单份原文256KiB、总原文1MiB；业务已有请求体上限也要满足。文件路径须在扫描根内、无跳转、标识／路径唯一。readStatus支持ok/failed/too_large/not_found；失败／无效XML／未知根／超限在 `sidecarDiagnostics` 留原因并回到原规则，不当空目录或清除旧身份。服务不下载任意URL，不需要网盘账号。

输出 `nfoEvidence` 含文档路径、原始修订／散列、分对象ID、作品与单集证据、冲突和原规则类型／年／ID。只读取XML根内直接字段；movie/tvshow/season/episodedetails分开，普通数字id保留unspecified，tmdbSet是collection，TMDB单集ID不进系列tmdbId。季0保留，负数／缺失不变1/1，单集年不当系列年；展示季集不覆盖规范位置。

同stem单集和电影资料精确关联；movie.nfo还要求完整单电影／同片多版本范围；tvshow.nfo只穿可验证的作品范围和结构节点，命名季目录前缀须官方别名核对；season.nfo不创建新作品。身份／季集冲突逐文件隔离待确认，不让一个坏NFO阻断同组其他文件。显式NFO作品ID先读一次共用身份，不逐文件按标题搜；单集位置按已有整季索引核对，有TMDB单集ID或日期时同时核对。

季资料须有明确季目录或已知系列范围，不能覆盖普通图片／资料目录。电影来源年和NFO年有差异时，用同一官方身份的发行年份核对；不整体放宽邻年。NFO改型保留原类型/年/季集/ID，电影清掉旧误集号，节目只恢复已收集的原文强季集。共享整剧NFO按作品合组，作用域/年份冲突分开裁决；无需联网的冲突／未知项不挤占正常作品的20组预算。

已确认身份与NFO冲突时保留人工身份，旧自动位置不冒充人工位置；自动经验遇到新强冲突会重新核实。人工只有身份、没有位置时，NFO位置可在逐文件隔离后共用本批20次整季预算。完整争议失效／纠错历史仍待完成，不声称已经实现完整生命周期。

真实12份NFO原文与早期散列全部一致，3电影／5单集／2季／2整剧。实际32次本机HTTP均200，官方核验选择7文件：3电影身份、1同stemNFO的S02E03及2既有明确位置可用；一个S05E25不在官方该季索引，仍pending，5589449只保留为单集ID。UUID／缺失视频的NFO不盲配。首轮补读6份必要资料，最终重放0新增、8份响应复用；没有AI请求。默认未启用NFO的182955文件逐项与v13一致。此演示不是独立正确率或APP接入验证。

v11 自动路径要求：完整文件标题／有结构依据的直接作品目录与官方名称或别名一致；唯一同类型、相容年份候选经详情核实；角色为正片，原编号、年份和季等强证据不冲突。不从任意远祖先或短词子串凑证据；错字／拼音只有模型建议而无独立桥梁时仍待确认。只有模型提供的电影年份不能单独成为自动消歧依据。跨作品编号暂不通过这条路径自动绑定。

`capabilities.automaticAiKnowledge=true` 表示支持自动写经验；`suggest` 成功返回 `confirmation=automatic_strong`、`knowledgeSaved=true` 和实际 `fileMappings`，位置未核实时仍为 pending。数据记录实际入模对象、模型／提示词／规则版本、原文片段、官方核验桥梁、身份与位置。人工身份受事务与条件更新保护；同修订不同自动身份保持冲突。写入失败另返回 `knowledgeSaved=false/persistenceError=knowledge_write_failed/retryable=true`，可复用短期建议重试，不重新请求模型补偿。
